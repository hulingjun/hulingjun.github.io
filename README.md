## 保存方式

当前是公开 GitHub Pages 网站，无需 Google Cloud、OAuth 密钥或额外后端。
登录 GitHub **hulingjun** 账号，使用仓库的“上传绘画作品”“保存知识空间”“写一条成长记录”模板。

知识编辑器的“保存到 GitHub”捕获当前空间快照，复制 JSON 后跳转提交。自动流程校验作者身份和数据，将知识保存到 content/knowledge/*.json，随记保存到 content/journal/*.json，再发布网站。只有自动回复确认成功才代表保存完成；本地缓存仅是恢复草稿，不是云端同步。

同一空间用稳定 spaceId 识别，最新提交编号为生效版本。旧记录和 Git 历史保留。打开 GitHub 空间会创建草稿副本，不覆盖原草稿。旧浏览器中的每个本地空间需要分别提交一次。单次网页提交限制 55000 字符，更大空间请先 JSON 备份并拆分。

编辑记录会更新，关闭会从网站下架，重开会恢复。关闭最新知识快照会回退到尚未关闭的较旧快照；全部关闭才会下架空间。已提交的知识文件和 Git 历史不自动删除。

## 画作与隐私

一条作品记录一张图片：JPG/PNG/WebP/GIF（首帧），最大 10 MB。HEIC 需先转 JPG。构建阶段校验 GitHub 附件域名、每次重定向、大小、MIME 与真实图片格式，自动校正方向，生成不裁切的 WebP 展示图与缩略图，移除元数据。

**GitHub 原始附件在上传后可能立即公开，网站去除元数据不等于清理原始附件。** 上传前移除位置、裁掉姓名、学校、地址。关闭记录不删除原始附件。不要提交密钥或私人信息。

不纳入贝贝、王洁、营养师、瑜伽、普拉提相关记录；相应文字校验只是防误收录，不是完整内容审查。

## 云端构建

GitHub Actions 在 main 更新、手动触发、作者本人更改成长记录时同步和部署。外部用户的 Issue 不会触发发布，构建读取记录时另以固定 GitHub 用户 ID 校验身份。Issue 文本只作为 JSON / 文字处理，不进入 shell，不执行代码。

archive-check 校验权限、解析、URL 安全、图片尺寸和去元数据、知识文件写入与正式构建。图片工具 sharp 0.35.4 在 Actions 临时目录独立安装，不改变现有应用依赖与锁文件。

部署失败保留线上上一次成功版本。下架仍需成功部署，错误详情在 Actions 以及提交记录的自动回复中。
